# Общие знания команды и агентов

Этот каталог — единая точка входа для всех, кто работает с проектом: людей
и субагентов. Здесь не дублируется ТЗ, а фиксируется **как требования
отображаются на реальный код, схему и интерфейс**.

## Состав

| Файл | Что внутри | Владелец |
|---|---|---|
| [`domain.md`](domain.md) | Глоссарий, роли, жизненный цикл визита и карты, инварианты И-1…И-15 | люди (read-only для агентов) |
| [`db.md`](db.md) | Карта БД: реальная миграция, целевая схема, расхождения, известные блокеры | `db` |
| [`api.md`](api.md) | Маршруты, HTMX-контракт, коды ответов, правила изменения API | `backend` |
| [`ui.md`](ui.md) | Карта экранов, структура CSS, правила интерфейса | `frontend` |
| [`decisions.md`](decisions.md) | Журнал решений (append-only) | все, по одной записи |

Смежные каталоги:

- [`../design/stylebook.md`](../design/stylebook.md) — стайлбук: токены, компоненты, состояния.
- [`../qa/README.md`](../qa/README.md) — стратегия тестирования и отчёты QA-агентов.
- [`../report/README.md`](../report/README.md) — рабочее место агента `report`.

## Правила

1. **Источник истины по требованиям — `ТЗ.md`.** Если knowledge противоречит ТЗ,
   прав ТЗ, а knowledge нужно исправить.
2. **Факт + ссылка.** Запись должна ссылаться на файл и, по возможности, строку:
   `internal/server/server.go:49`.
3. **Не копировать DDL и большие таблицы.** В `db.md` — карта и расхождения,
   точные колонки — в миграциях.
4. **Обновлять вместе с кодом.** Изменил поведение, схему или маршрут — в том же
   изменении обнови свой раздел.
5. **Решения — отдельно.** История «почему так» живёт в `decisions.md`, а не в
   разделах.
6. **Чужой раздел не правим.** Нужна правка — обратись к владельцу раздела.

## Формат записи в `decisions.md`

```md
| 2026-11-25 | team | Введены субагенты по блокам | ... | принято |
```

Одна строка — одно решение. Если объяснение длиннее двух предложений, добавь
под таблицей подраздел `### D-<номер>: <название>`.

## Быстрый старт для агента

1. Прочитай `AGENTS.md` в корне.
2. Прочитай `ТЗ.md` (свой раздел требований) и `docs/knowledge/domain.md`.
3. Открой раздел знаний своего блока.
4. Проверь фактическое состояние по коду, а не только по документу.
5. После работы обнови свой раздел и, если решение нетривиальное, `decisions.md`.
