# API и HTMX-контракт

Владелец раздела — агент `backend`. Любое изменение URL, полей формы или
HTMX-фрагмента сначала фиксируется здесь, потом в коде.

## 1. Текущие маршруты

| Метод | Путь | Ответ | Файл |
|---|---|---|---|
| `GET` | `/healthz` | JSON `{"status":"ok","db":"ok"}`, `503` при недоступной БД | `internal/server/server.go:52` |
| `GET` | `/static/*` | статика из `web/static` | `internal/server/server.go:53` |
| `GET` | `/` | HTML, экран «Смена» | `internal/server/server.go:54` |

## 2. Планируемая структура

Роуты раскладываются по файлам-модулям, чтобы не конфликтовать в git:

```
internal/server/
  routes_auth.go      вход, выход, сессия
  routes_visits.go    открытие/закрытие визита, услуги
  routes_cards.go     пул карт, выдача, возврат
  routes_guests.go    гости, скидки
  routes_rooms.go     комнаты и цены
  routes_reports.go   отчёты и экспорт
  routes_admin.go     сотрудники, роли, настройки
```

## 3. Правила ответов

- **HTML first.** Основной интерфейс — серверные шаблоны; JSON только для
  health-check и внешних интеграций.
- **POST → 303 See Other** (Post/Redirect/Get), чтобы F5 не повторял операцию.
- **HTMX-фрагменты** возвращают HTML-партиал, а не JSON и не целую страницу.
- **Ошибки валидации** — `400` и та же форма с подсветкой полей и введёнными
  значениями; не JSON.
- **Нет прав** — `403`; **не найдено** — `404`; **конфликт состояния** — `409`
  (карта уже в визите, визит уже закрыт, смена уже закрыта).
- **Идемпотентность.** Повторный скан карты с активным визитом возвращает
  текущий визит, а не создаёт новый.
- **Сессии** — серверные cookie (`HttpOnly`, `SameSite=Lax`, `Secure` в prod),
  не JWT.
- **CSRF** — токен в каждой форме, изменяющей состояние.

## 4. Соглашения HTMX

| Атрибут | Правило |
|---|---|
| `hx-get` / `hx-post` | только на элементы, которые действительно меняют фрагмент |
| `hx-target` | явный `id`, не `body` |
| `hx-swap` | по умолчанию `innerHTML`; для таблиц — `beforeend`/`outerHTML` осознанно |
| `HX-Trigger` | события вида `visit-updated`, `card-returned`, `payment-accepted` |
| `hx-confirm` | только для разрушающих действий |

Фрагменты лежат в `web/templates/fragments/<screen>/<part>.html`.

## 5. Формат ошибок

Для JSON-эндпоинтов:

```json
{ "error": "card_already_in_use", "message": "Карта уже участвует в визите" }
```

Для HTML — блок `.form-error` над формой и текст у конкретного поля.

## 6. Протокол изменений

1. Обнови этот файл: метод, путь, поля, коды, фрагмент.
2. Если изменение ломает существующий вызов — добавь запись в
   [`decisions.md`](decisions.md) и предупреди `frontend`.
3. Обнови тесты в `*_test.go` (их пишет `qa-backend`).
4. Только после этого меняй обработчик.
