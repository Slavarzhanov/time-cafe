## 2. Тестовые файлы

```
tests/db/
  schema.sql        типы, ограничения, индексы
  invariants.sql    И-1…И-15 на данных
  seed.sql          проверка повторной загрузки
  reports.sql       запросы отчётов и EXPLAIN
```

Каждый файл запускается отдельно:

```powershell
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" `
  -h localhost -p 5432 -U postgres -d timecafe_test `
  -v ON_ERROR_STOP=1 -f tests/db/invariants.sql
```

## 3. Подготовка тестовой БД

```sql
DROP DATABASE IF EXISTS timecafe_test;
CREATE DATABASE timecafe_test;
```

Затем — миграции из `migrations/` в порядке версий. Рабочую базу `timecafe`
не используем.

## 4. Известные проблемы (на момент создания)

- `000001_init.up.sql` описывает старую модель: постоянная привязка карты,
  баланс, тарифы. Проверки И-5…И-7, И-11, И-15 на ней неприменимы до
  переработки `db`.
- `00002_init_sql_test.sql` не запускается: `UNIQUE … INCLUDE` с той же
  колонкой, нет `CREATE SCHEMA`, пустой `statuses`.
- `checks.sql` использует `timecafeschema`, а рабочая миграция — `public`.
- Раннер не применяет `checks.sql`.

Эти пункты фиксируются как **Blocker** в отчёте, а не обходятся тестами.
