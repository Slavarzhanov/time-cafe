# Тестирование TimeCafe

Стратегия и отчёты QA-агентов. Тестирование — отдельная роль: QA-агенты
**не правят production-код**, они пишут тесты, воспроизводят дефекты и отдают
отчёт владельцу блока.

## 1. Агенты и зоны

| Агент | Блок | Что пишет | Куда отчёт |
|---|---|---|---|
| `qa-db` | база данных | `tests/db/*.sql`, `*_test.go` для БД | [`db.md`](db.md) |
| `qa-backend` | Go-бэкенд | `*_test.go`, `testdata/` | [`backend.md`](backend.md) |
| `qa-frontend` | шаблоны и UI | `*_test.go`, `testdata/` | [`frontend.md`](frontend.md) |

Владельцы блоков: `db`, `backend`, `frontend`, `style`. QA не исправляет их
код сам — он формулирует дефект и передаёт владельцу.

## 2. Уровни

| Уровень | Что проверяет | Инструмент |
|---|---|---|
| **Модульный** | биллинг, округление, скидки, валидация UID | `go test` |
| **Интеграционный** | HTTP + БД, миграции, ограничения, репозитории | `go test`, `psql` |
| **Сквозной** | сценарий «скан → визит → услуги → закрытие → чек» | ручной прогон / e2e |
| **Приёмочный** | критерии К-1…К-14 из ТЗ | чек-лист + демо |

## 3. Команды

```powershell
# всё
go test ./...
go test -race ./...
go test -cover ./...
go vet ./...
go build ./...

# только БД (когда появятся тесты)
go test ./internal/db/... ./internal/storage/...

# SQL-тесты
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" `
  -h localhost -p 5432 -U postgres -d timecafe_test `
  -v ON_ERROR_STOP=1 -f tests/db/invariants.sql
```

`psql` не в `PATH`; на Windows используем полный путь.

## 4. Тестовая БД

- Отдельная база `timecafe_test`; рабочую `timecafe` не трогаем.
- Перед прогоном: `DROP DATABASE IF EXISTS timecafe_test; CREATE DATABASE timecafe_test;`
- Миграции применяются теми же файлами, что и в production.
- Каждый SQL-тест оборачивается в `BEGIN … ROLLBACK`, если он не проверяет
  саму миграцию.
- Seed-данные — только в тестовой БД.

## 5. Трассировка инвариантов

| Инвариант | Кто проверяет | Где |
|---|---|---|
| И-1 деньги в копейках | `qa-db` | типы колонок, `tests/db/schema.sql` |
| И-2 итог визита | `qa-backend` | unit-тест биллинга |
| И-3 нельзя закрыть дважды | `qa-backend` + `qa-db` | handler + constraint |
| И-4 `finished_at ≥ started_at` | `qa-db` | CHECK |
| И-5 один активный визит гостя | `qa-db` | partial unique / EXCLUDE |
| И-6 карта в одном активном визите | `qa-db` | partial unique |
| И-7 карта не выдана повторно | `qa-backend` + `qa-db` | сценарий + constraint |
| И-8 услуги закрытого визита | `qa-backend` | handler |
| И-9 цена на момент добавления | `qa-backend` + `qa-db` | `price_at_moment` |
| И-10 UID и номер уникальны | `qa-db` | UNIQUE + CHECK regex |
| И-11 сумма платежей = итог | `qa-backend` + `qa-db` | проверка при закрытии |
| И-12 цена комнаты неизменна | `qa-db` | триггер/проверка |
| И-13 брони не пересекаются | `qa-db` | EXCLUDE |
| И-14 визит в открытой смене | `qa-backend` + `qa-db` | FK + проверка |
| И-15 скидка ≤ стоимость времени | `qa-backend` | unit-тест |

## 6. Уровни дефектов

| Уровень | Значение | Пример |
|---|---|---|
| **Blocker** | сценарий невозможен, данные теряются | нельзя закрыть визит, миграция не применяется |
| **Major** | неверный результат, обходной путь есть | неверная сумма, карта выдана дважды |
| **Minor** | неудобство, косметика | съехавшая подпись, неверный отступ |
| **Trivial** | опечатка | текст ошибки с ошибкой |

## 7. Формат отчёта

```md
## 2026-11-25 · qa-backend · прогон 1

Команда: `go test ./...`
Результат: 12 passed, 1 failed

### Blocker
- `internal/billing/calc_test.go:42` — при округлении вверх 61 минута
  тарифицируется как 60. Ожидалось 90 (шаг 30).
  Воспроизведение: `go test ./internal/billing -run TestRoundUp`
```

## 8. Definition of Done для теста

- [ ] Есть команда, которая воспроизводит проверку.
- [ ] Тест детерминирован: без `sleep`, без зависимости от текущего времени.
- [ ] Тест не требует рабочей БД и реальных карт.
- [ ] При падении видно, что именно сломалось.
- [ ] Отчёт обновлён в `docs/qa/<блок>.md`.
